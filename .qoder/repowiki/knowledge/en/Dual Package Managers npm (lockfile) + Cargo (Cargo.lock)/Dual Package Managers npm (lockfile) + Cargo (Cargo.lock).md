## Overview

The FreeSpace macOS desktop app is a hybrid Tauri project with two independent dependency graphs:

- **Frontend** (TypeScript/Vite): managed by **npm** via `package.json` and `package-lock.json`.
- **Backend** (Rust/Tauri v2): managed by **Cargo** via `src-tauri/Cargo.toml` and `src-tauri/Cargo.lock`.

There is no cross-language lockfile, no vendored dependencies, and no private registry configuration in the repository. Both managers resolve from their default public registries (npmjs.org for npm, crates.io for Cargo).

## Frontend (npm)

- Declaration file: `package.json`
- Lockfile: `package-lock.json` (lockfileVersion 3)
- No `.npmrc`, no `pnpm-lock.yaml`, no `yarn.lock` — npm is the sole package manager.
- Dependencies are declared under `dependencies` and `devDependencies`:
  - Runtime deps: `@tauri-apps/api` (`^2`), `@tauri-apps/plugin-opener` (`^2`).
  - Dev deps: `@tauri-apps/cli` (`^2`), `vite` (`^6.0.3`), `typescript` (`~5.6.2`).
- Version ranges use caret (`^`) for major-version-compatible updates and tilde (`~`) only for TypeScript to pin patch-level changes.
- The `scripts` field wires npm into the build pipeline (`dev`, `build`, `preview`, `tauri`) but does not call any custom install/update scripts.
- No `overrides`, `resolutions`, or `workspaces` fields — single-package setup.

## Backend (Cargo)

- Manifest: `src-tauri/Cargo.toml`
- Lockfile: `src-tauri/Cargo.lock` (generated by Cargo; header states it is "automatically @generated" and "not intended for manual editing").
- Direct Rust dependencies:
  - `tauri = { version = "2", features = [] }`
  - `tauri-plugin-opener = "2"`
  - `serde = { version = "1", features = ["derive"] }`
  - `serde_json = "1"`
  - `walkdir = "2"`
  - `trash = "5"`
  - `dirs = "6"`
  - Build-time dep: `tauri-build = { version = "2", features = [] }`
- Platform-scoped dependencies via `[target.'cfg(target_os = "...")'.dependencies]`:
  - macOS: `libc = "0.2"`
  - Windows: `windows-sys = { version = "0.59", features = ["Win32_Storage_FileSystem"] }`
- All versions use semver-compatible ranges (no exact pins except where Cargo itself resolves them in `Cargo.lock`).

## Vendoring & Private Registries

- No `vendor/` directory exists under either `node_modules` or Cargo's vendored layout.
- No `.npmrc`, `cargo config.toml`, `CARGO_HOME`, `GOPRIVATE`, or similar files are present at the repo root or under `src-tauri/`.
- `package-lock.json` entries contain `resolved` URLs pointing directly at `https://registry.npmjs.org/...` and include `integrity` hashes — confirming npm's default registry and integrity verification.
- `Cargo.lock` entries contain `source = "registry+https://github.com/rust-lang/crates.io-index"` — confirming Cargo's default crates.io index.

## Conventions Observed

- Each language ecosystem keeps its own manifest and lockfile independently; there is no orchestration layer that synchronizes versions across the two.
- Versioning strategy differs between ecosystems: frontend uses broad caret ranges (`^2`, `^6.0.3`) while the one precise pin (`~5.6.2` for TypeScript) suggests a preference for patch stability on toolchain packages.
- Platform-specific Rust dependencies are isolated using Cargo's `cfg(target_os = ...)` target selectors rather than feature flags.
- The Tauri CLI is installed as an npm devDependency (`@tauri-apps/cli`) and invoked via `npm run tauri`, keeping the Rust-side Tauri tooling separate from the Node-side CLI wrapper.

## Rules / Enforced Constraints

- `package-lock.json` is committed alongside `package.json`; npm will enforce resolution against this lockfile when `install` is run (enforced by npm's lockfile semantics, documented in npm docs).
- `Cargo.lock` is committed under `src-tauri/`; the file header explicitly states it is auto-generated and not for manual editing (enforced by Cargo convention and CI expectations for reproducible builds).
- No private registries or authentication tokens are configured in the repository — all dependencies resolve from public registries (npmjs.org, crates.io).
