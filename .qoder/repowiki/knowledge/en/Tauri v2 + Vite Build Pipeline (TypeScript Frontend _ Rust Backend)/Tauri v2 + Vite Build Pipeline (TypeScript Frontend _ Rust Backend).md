## Overview

The project is a Tauri v2 desktop application composed of two independently built layers:
- **Frontend**: TypeScript + Vite, producing a static site under `dist/`.
- **Backend**: Rust crate (`freespace-macos`) built via Cargo and the Tauri build system.

There are no Makefiles, shell scripts, Dockerfiles, or CI configuration files in the repository. The entire build flow is driven by the Tauri CLI (`@tauri-apps/cli`) orchestrating npm/Vite and Cargo.

## Entrypoints and Scripts

- `package.json` defines four npm scripts:
  - `npm run dev` → `vite` (standalone frontend dev server).
  - `npm run build` → `tsc && vite build` (TypeScript compilation then Vite production build).
  - `npm run preview` → `vite preview`.
  - `npm run tauri` → `tauri` (delegates to `@tauri-apps/cli`).

- `src-tauri/Cargo.toml` declares the Rust package `freespace-macos` (edition 2021) with crate types `staticlib`, `cdylib`, and `rlib`. Dependencies include `tauri = "2"`, `tauri-plugin-opener`, `serde`, `serde_json`, `walkdir`, `trash`, `dirs`, plus platform-scoped deps: `libc` on macOS and `windows-sys` on Windows.

- `src-tauri/build.rs` is a thin shim that calls `tauri_build::build()`, which generates the Tauri capability schemas and ACL manifests under `src-tauri/gen/schemas/`.

## Tauri Configuration

`src-tauri/tauri.conf.json` is the single source of truth for the app bundle:
- `productName`: `FreeSpace`
- `version`: `0.1.0` (mirrors `package.json` version)
- `identifier`: `com.freespace.macos`
- `build.beforeDevCommand`: `npm run dev`
- `build.devUrl`: `http://localhost:1420`
- `build.beforeBuildCommand`: `npm run build`
- `build.frontendDist`: `../dist`
- `bundle.targets`: `all` (produces all supported Tauri targets)
- `bundle.icon`: lists PNG variants, `icon.icns`, and `icon.ico` under `src-tauri/icons/`.

## Vite Configuration

`vite.config.ts` configures the frontend dev server:
- Fixed port `1420` with `strictPort: true` (Tauri expects this exact port).
- HMR host/port come from the `TAURI_DEV_HOST` environment variable when running inside Tauri dev.
- Watches everything except `**/src-tauri/**` so Rust changes do not trigger unnecessary frontend rebuilds.
- `clearScreen: false` prevents Vite from obscuring Rust compiler errors during `tauri dev`.

## Versioning Strategy

Version numbers are duplicated across three locations and must be kept in sync manually:
1. `package.json` → `version: "0.1.0"`
2. `src-tauri/Cargo.toml` → `version = "0.1.0"`
3. `src-tauri/tauri.conf.json` → `version: "0.1.0"`

There is no automation to synchronize these values.

## Icon Generation

Icons are generated by `generate_icon.py`, a standalone Python script using `Pillow` and `numpy`. It renders a 1024×1024 squircle-shaped icon with gradient background, neon ring, storage plate, and broom graphics, saving to a hardcoded path `/Volumes/SSD.DATA/Leo/APPS/FreeSpaceMacos/app-icon-1024.png`. This script is not wired into any build step — it is a manual pre-build asset generator.

## Dependency Management

- Frontend: npm via `package.json` + `package-lock.json`.
- Backend: Cargo via `Cargo.toml` + `Cargo.lock`.
- No vendoring; dependencies are fetched from crates.io and npm registries at build time.

## Conventions Observed

- The frontend and backend live in separate directories (`src/` vs `src-tauri/`) and are built independently, then merged by Tauri's bundler.
- Tauri v2 is used throughout: `@tauri-apps/api` ^2, `@tauri-apps/cli` ^2, `tauri = "2"`, `tauri-build = "2"`, and the config schema URL points to `https://schema.tauri.app/config/2`.
- Platform-specific code is gated with Cargo target cfgs (`cfg(target_os = "macos")`, `cfg(target_os = "windows")`) rather than runtime checks.
- The app identifier uses reverse-DNS style (`com.freespace.macos`).
- The dev server port is hard-coded to `1420` in both `vite.config.ts` and `tauri.conf.json`.

## Rules Enforced by the Build System

- Running `tauri dev` requires `npm run dev` to be available and will fail if port `1420` is already occupied (`strictPort: true`).
- Running `tauri build` runs `npm run build` first and fails if the frontend does not emit assets into `../dist` as expected by `frontendDist`.
- The Rust build invokes `tauri_build::build()` unconditionally, so capability schemas under `src-tauri/gen/schemas/` are regenerated on every Rust compile.
- Bundle generation is enabled (`bundle.active: true`) and targets `all` platforms; omitting required icons from `src-tauri/icons/` would cause bundling to fail.

## Notable Absences

- No `Makefile`, `.sh` build scripts, `Dockerfile`, or GitHub Actions/GitLab CI pipeline exist in the repository.
- No cross-compilation toolchain configuration is present beyond Cargo's native target cfgs.
- No automated release or publishing workflow is defined.
