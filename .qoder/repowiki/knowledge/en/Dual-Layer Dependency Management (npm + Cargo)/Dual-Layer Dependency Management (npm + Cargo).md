## Approach

The repository manages dependencies for two independent toolchains side by side:

- **Frontend** — npm / Node.js, managed via `package.json` with a lockfile.
- **Backend** — Rust (Tauri v2), managed via `Cargo.toml` with a lockfile.

There is no cross-language dependency resolver; each language ecosystem pins its own third-party packages independently.

## Frontend (npm)

- Manifest: `package.json` at the repo root.
- Lockfile: `package-lock.json` at the repo root (generated by npm).
- Package manager: npm (lockfile name and presence imply npm; no pnpm/yarn lockfile exists).
- Dependencies declared in two sections:
  - `dependencies`: runtime deps — `@tauri-apps/api` (`^2`) and `@tauri-apps/plugin-opener` (`^2`).
  - `devDependencies`: build/dev tools — `@tauri-apps/cli` (`^2`), `vite` (`^6.0.3`), `typescript` (`~5.6.2`).
- Versioning strategy uses caret (`^`) for major-version-compatible ranges on most packages, and tilde (`~`) for TypeScript to pin minor/patch.
- No private registry or `npmrc` configuration is present in the tree; packages are resolved from the default public npm registry.
- The project is marked `"private": true`, preventing accidental publication to the npm registry.

## Backend (Rust/Cargo)

- Manifest: `src-tauri/Cargo.toml`.
- Lockfile: `src-tauri/Cargo.lock` (generated by Cargo).
- Edition: `2021`.
- Runtime dependencies:
  - `tauri = "2"` (with empty `features = []`).
  - `tauri-plugin-opener = "2"`.
  - `serde = { version = "1", features = ["derive"] }`.
  - `serde_json = "1"`.
  - `walkdir = "2"`.
  - `trash = "5"`.
  - `dirs = "6"`.
- Build-time dependency: `tauri-build = { version = "2", features = [] }` under `[build-dependencies]`.
- Target-specific dependencies:
  - macOS-only: `libc = "0.2"` under `[target.'cfg(target_os = "macos")'.dependencies]`.
  - Windows-only: `windows-sys = { version = "0.59", features = ["Win32_Storage_FileSystem"] }` under `[target.'cfg(target_os = "windows")'.dependencies]`.
- Crate output: produces `staticlib`, `cdylib`, and `rlib` via `[lib] crate-type`, allowing Tauri to link it as a native library.
- No `cargo config.toml`, `.cargo/config.toml`, or `CARGO_REGISTRY_*` environment variables indicating a private registry; crates are sourced from crates.io.

## Conventions Observed

- Each language layer owns its own manifest and lockfile; there is no shared dependency graph between the frontend and backend.
- Tauri-related packages use major-version wildcards (`^2` for JS, `"2"` for Rust) so that minor/patch updates within the Tauri v2 series are accepted automatically.
- Platform-scoped dependencies are isolated using Cargo's `cfg(target_os = ...)` selectors rather than feature flags.
- The frontend build script runs `tsc && vite build`, meaning TypeScript compilation is a separate step before Vite bundling.
- No vendored dependencies directory (no `node_modules/` committed, no `vendor/` for Rust); both ecosystems rely on their package managers to fetch and cache dependencies.
